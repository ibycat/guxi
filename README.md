# guxi · A股 / 港股 股息率排行榜

一个纯前端 + 一个边缘代理函数的股息率排行榜，同时覆盖 **A 股全市场**与**港股**，部署在 Cloudflare Pages 上。
打开即用，无需数据库、无需构建、无第三方框架。

**线上地址：https://guxi-6em.pages.dev**

## 功能

- **A 股**：全市场约 5,500 只实时股息率排行，红涨绿跌
- **港股**：默认港股通 668 只，可切换全部港股（自动剔除仙股）
- 三种口径一键切换：**TTM 滚动 12 个月 / 上年年报 / 近 3 年平均**
- 可排序表格 + 多条件筛选（行业、股息率、市值、剔除 ST/次新）+ 4 个预设（稳健高息 / 周期高息 / 待核验）
- 点击任意一行展开逐条分红明细（A 股：报告期 / 每 10 股派息 / 除权除息日 / 方案进度；港股：年度类型 / 每股派息含币种 / 除净日）
- 质量标记：分红不连续、分红率 > 90%、周期高位、含 2 次年报、需核验、稳健、非港币派息、低价股
- 右侧行业股息率分布条形图
- 导出当前筛选结果为 CSV
- 行情 5 分钟自动刷新，localStorage 缓存 12 小时（二次打开秒出，仅 A 股）

## 架构

```
                     ┌─ 首选：预生成快照（秒开）
浏览器 ──► /api/snap?f=a|hk ──► GitHub data 分支的快照 JSON（边缘缓存 5 分钟 + gzip）
   │
   └─ 兜底：实时聚合
        /api/em?u=...   单接口代理（分级缓存 + 分页预热）──► 东方财富
        /api/hk?mode=... 港股聚合（边缘侧拉全部分页）    ──► 东方财富
             └─ 都不可用（静态托管 / 本地 file://）→ JSONP 直连
```

- `index.html`：单文件应用（内联 CSS / JS），只依赖同源 `/api/em`
- `functions/api/em.js`：同源代理
  - 域名白名单：`push2.eastmoney.com`、`datacenter-web.eastmoney.com`、`datacenter.eastmoney.com`
  - 剔除 JSONP 回调参数与 `_` 时间戳（否则边缘缓存永不命中）
  - 行情缓存 60s、分红/派息缓存 12h（A 股 `RPT_SHAREBONUS_DET` 与港股 `RPT_HKF10` 同一策略）
  - 命中冷缓存时用 `waitUntil` 后台预热后续 8 页，避免逐页串行回源
  - 429 / 5xx 自动退避重试，上游返回 HTML 验证页时判定为失败

加代理的原因：东方财富接口不返回 CORS 头，直连只能靠 JSONP（无法缓存、易被拦截）；走自己的域后既能缓存，也不怕浏览器拦截第三方脚本。

> 注意：仓库里**不要放 `package.json`**。Pages 一旦检测到 `wrangler` 依赖，会自动改用 `wrangler deploy`（Worker 模式）并报 `Missing entry-point`。本项目走纯静态上传 + `functions/` 自动挂载。

## 数据源

| 市场 | 用途 | 接口 | 单页上限 |
| --- | --- | --- | --- |
| A 股 | 行情 / 行业 / PE / PB / 市值 / 上市日 | `push2.eastmoney.com/api/qt/clist/get`（`fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23`） | 100 |
| A 股 | 分红送配 | `datacenter-web.eastmoney.com` → `RPT_SHAREBONUS_DET` | 500 |
| 港股 | 港股通行情 | 同上 `push2`，板块 `b:DLMK0146`（668 只） | 100 |
| 港股 | 全部港股行情 | 同上 `push2`，`m:128+t:1,t:2,t:3,t:4` | 100 |
| 港股 | 派息记录 | `datacenter.eastmoney.com/securities/api/data/v1/get` → `RPT_HKF10_MAIN_DIVBASIC` | 500 |

A 股与港股用的是**两张不同的分红报表**（`RPT_SHAREBONUS_DET` 查港股代码返回空），这是必须分开两条管线的原因。

## A 股口径

| 指标 | 定义 |
| --- | --- |
| 股息率 TTM | 近 12 个月内**已实施除权**的现金分红合计 ÷ 现价 |
| 上年年报 | 上一完整会计年度现金分红 ÷ 现价 |
| 近 3 年平均 | 近 3 个年度派息合计 ÷ 现价 ÷ 年数 |
| 分红率 | 上年年报每 10 股派息 ÷ 10 ÷ 上年基本每股收益 |
| 连分年数 | 近 6 年窗口内连续分红的年数，`6+` 表示窗口内每年都有 |

口径说明：

- **只算现金分红**，送转股不计入股息率
- 榜首常见 10%+ 多为一次性特别分红或两次年报挤进同一窗口，已用 `含 2 次年报`、`需核验` 标记
- 周期行业（煤炭、航运、化工等）盈利顶部股息率虚高，次年易腰斩，标记为 `周期高位`

## 港股口径

### 为什么默认只统计港股通

港股 tab 默认走港股通（`b:DLMK0146`，668 只），勾选「含全部港股」才切到全量。原因：

| 维度 | 港股通（668 只） | 全部港股（过滤后约 2,600 只） |
| --- | --- | --- |
| 可交易性 | 境内资金实际能买 | 大部分陆资买不到 |
| 数据质量 | 交易所预筛市值、流动性、合规 | 仙股、老千股混杂 |
| 股息率可信度 | 高 | 低：0.2 港元股价派 0.02 港元算出 10%，但没有成交量 |
| 性能 | 7 页行情请求 | 26 页 |

港股的高股息陷阱与 A 股不同：**A 股是「分红不可持续」，港股更常见的是「分数很高但根本没有成交量」**。所以「含全部港股」模式下会强制剔除股价 < 1 港元或市值 < 20 亿港元的标的，否则榜首会被仙股占满。

港股通名单由接口实时返回，不需要手工维护成分表。

### 指标定义

| 指标 | 定义 |
| --- | --- |
| 股息率 TTM | 近 12 个月内**已除净**的**港币**现金派息合计 ÷ 现价 |
| 上年年报 | 最近有派息年度的港币派息合计 ÷ 现价 |
| 近 3 年平均 | 近 3 个年度港币派息合计 ÷ 现价 ÷ 有派息年数 |
| 连分年数 | 按 `YEAR` 字段汇总，近 6 年窗口内连续有派息的年数 |
| 分红率 | **不提供**（显示 `—`），见下方取舍 |

### 币种与派息解析

派息金额从 `PLAN_EXPLAIN` 文本解析，形如「每股派港币0.922元」：

- **港币派息直接计入；其他币种按固定汇率折算成港币后计入**，并打 `含非港币(已折算)` 标记
- 折算汇率：人民币 1.08、美元 7.78、新加坡元 5.8、澳元 5.1（固定值，仅供横向比较）
- 只统计**已除净**记录（`EX_DIVIDEND_DATE <= 今天`），已公告未除净的预案不会提前算进 TTM

为什么必须折算：实测港股通 665 只里，**265 只只用人民币派息、28 只只用美元**，只算港币会让 300 多只被判成「无分红」，有效样本从 500+ 掉到 143 只。

### 已知取舍

- **港股分红率留空**：东财港股 F10 的每股收益需要逐只查询，668 只逐个请求不现实，宁可留空也不填假数字
- 汇丰、太古这类以美元/人民币派息的公司会被低估，但页面有 `非港币派息` 标记
- 合股/拆股会导致每股派息金额断层，跨年比较可能失真，未做复权处理
- 港股暂不做 localStorage 缓存（A 股仍缓存 12 小时）

## 数据更新机制

站点默认读**预生成快照**，实时接口只作兜底。

```
GitHub Actions (cron */30) ──► scripts/snapshot.mjs ──► data 分支（单提交 force-push）
                                                              │
                                         /api/snap 边缘代理 ◄──┘
```

- 为什么要用 Actions 而不用 Cloudflare Cron：Pages Functions 没有 Cron Trigger；更关键的是**东财对 Cloudflare 出口 IP 有风控**，抓多了直接 502，而 GitHub Runner 的出口 IP 完全不同
- 为什么快照不提交到 `main`：Pages 免费版每月只有 **500 次构建**，每 30 分钟一次会打爆配额。改为独立的 `data` 分支 + 单提交 force-push，既不影响构建配额，也不会撑大 `main` 的历史
- 为什么还要 `/api/snap` 代理：`raw.githubusercontent.com` 在国内又慢又不稳（1.5MB 实测要 50 秒），同源代理走 Cloudflare 边缘，顺手 gzip（A 股 1.47MB → 360KB，港股 196KB → 44KB）
- 回源失败时返回上一次成功缓存的副本，宁可给旧数据也不给空白

实测首屏（快照路径）：港股 44KB / A 股 360KB（gzip 后），边缘缓存命中后为单次静态请求量级；未预热的首个边缘节点需要多花 1~2 秒拉一次快照。

## 部署

### Dashboard（当前使用的方式）

Workers & Pages → 创建 → Pages → 连接 GitHub → 选本仓库：

| 配置项 | 值 |
| --- | --- |
| 项目名称 | `guxi` |
| 生产分支 | `main` |
| 框架预设 | 无 |
| 构建命令 | 留空 |
| 构建输出目录 | `.` |

`functions/` 会被自动识别为 Pages Functions。

### CLI

```bash
npx wrangler pages deploy . --project-name guxi
```

### 本地开发

```bash
npx wrangler pages dev . --port 8788
```

不装 wrangler 也能用：直接双击 `index.html`，会自动回退到 JSONP 直连模式（A 股与港股都可以）。

## 已知限制

- 东方财富 `push2` 列表接口单页上限 100 条（A 股全市场需 56 次分页请求）；`datacenter` 分红接口单页上限 500 条
- 首次冷缓存仍需拉取全量分页，之后 12 小时内命中边缘缓存
- A 股采用两段式加载：先出 TTM 榜单，历史年报在后台静默补齐（补齐前「连分年数」显示 `…`）
- 港股一次性拉取近 6 年派息，无两段式拆分，首屏比 A 股慢
